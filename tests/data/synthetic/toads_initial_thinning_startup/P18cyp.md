# P18cyp rigid registration and wrapper control slice

This slice consumes P18cyo's exact 25×25×25 RAS membership map and objective,
which are checked against `continuation_java_reference.json` before use. It
registers the 11-class map against the folded synthetic shape field with the
selected wrapper defaults: rigid transform, class 0 excluded, offset 0,
subsample 2, up to five updates, minimum energy change `1e-6`, and minimum
lambda `1e-3`. It then applies the selected wrapper's float32 energy-ratio and
stop/iteration control kernel.

No membership pass is recomputed. The source's post-thinning
`computeCorrectionField(deg)` refit is deliberately not ported in this slice;
P18cyo correction fields remain fixed.

## Java source and numerical evidence

The selected call order is pinned to the supplied VandyCRUISE sources:

* `AlgorithmMultipleToads.java` (`b6ee1cd14dc0ad5eb7a3c0e9809ce19978c3381b233bfcc752ab070a50bbf01d`), lines 766–810: exact membership/objective, energy ratio, optional `atlas.registerShapes()`, stop/iteration decisions, growth and classification/relation branch.
* `MultipleToadDeformableAtlas.java` (`e949505a3ccdd63745fea7ba8a1dd5a67d5c4c4eb9644553d1d63beb6217a9e2`), lines 2718–2742: `registerShapes()` dispatch and `registerAllShapes()` reset/iteration/finalization.
* Registration helpers: `ParametricTransform.java` (`22bd0cf545bf1112f24096be54e7688638bbcdbd6224e69dc6c74ea240063fac`), `RotationMatrix.java` (`144d16dc33eca12a4a3a117c362b7aa1e767fe6561950f64ef04a66297818af0`), and `ImageFunctions.java` (`be0eae41dd1487de200930e72ed22a3585402caf7a04484180bbb45d77468892`).

The first broad compile attempt searched all MIPAV source files and failed on
four unrelated ambiguous `MipavCoordinateSystems` references. Narrowing the
source path to VandyCRUISE and supplying the small stubs under
`tests/java_reference/stubs/` compiled the actual selected atlas class and its
transitive registration helpers. The committed
`ToadsP18cypActualRegistrationHarness.java` calls the supplied class' actual
`updateShapeRegistration(..., "rigid", 5, ...)`, `registerShapes()`, and
private `registerAllShapes()` methods on the exact P18cyo membership array and
folded shape array generated by the focused test. Test-only stubs replace only
MIPAV token parsing and progress-message output; the transform, coefficient,
line-search, energy, and bounding-box methods execute from VandyCRUISE source.
The harness obtains final energy by invoking the selected private
`computeExactRegistrationEnergy()` method.

The focused comparison checks all five source `H`/`G` coefficient pairs,
lambda and trial energy at each update, reconstructed trial transforms, final
transform and energy, and all 11 final shape bounds against Python. The
registration kernel samples the full subject lattice, matching the Java
source; shape bounds are outputs and are not used to clip the optimizer's
sampling domain. The exact P18cyo membership digest/objective are also checked
against `continuation_java_reference.json` before registration. This validates
the bounded registration/control composition on this synthetic state, not the
whole TOADS workflow. The correction-field refit, growing/classification or
relation branches, later iterations, and actual imaging data remain outside
this slice.

The headless compile/run script expects the supplied VandyCRUISE source tree
beside the pymacruise checkout. Run the focused Java/Python comparison with:

```sh
.venv/bin/pytest -q tests/test_toads_initial_registration_control.py
```
