# P18czn synthetic atlas-aware approximate-membership reference

The numerical inputs reuse the P18czl fixture:

- `../toads_lesion_atlas_type_membership/images.nii.gz`: asymmetric 9×8×7,
  two-channel, true-RAS synthetic subject intensities.
- `../toads_lesion_atlas_type_membership/transformed_shapes.nii.gz`: thirteen
  current-transform atlas priors on the subject grid, including folded
  cortex-like structure.
- `../toads_lesion_atlas_type_membership/atlas_template_shapes.nii.gz`:
  thirteen template-space priors on a distinct 11×10×9 true-RAS grid.

This slice uses `approx=3` and validates only the atlas-aware initial
membership overload. `images.nii.gz` and `transformed_shapes.nii.gz` supply
the exact input grids to the method harness. The separate template-shape file
is checked for 13-class fixture identity, but is not consumed by this method.
Java reference output in `java_reference.json` is generated by
`tests/java_reference/generate_toads_lesion_approximate_registration_reference.sh`.
The harness reads repository-local fixture/descriptor files and compiles
against copied utility sources under `tests/java_reference/upstream`; it does
not require the supplied source checkout at test time. Its selected-source
hashes identify `AlgorithmMultipleToads`, `MultipleToadPreprocess`, and
`MultipleToadDeformableAtlas`; the test also distinguishes the dedicated
`AlgorithmLesionToads` wrapper.

The reference captures all initialized top-k membership values and class
candidate slots for the 9×8×7 synthetic subject, plus Java-pinned strict-tie
and zero-cost cases. Its source call-site metadata records the later
`AlgorithmMultipleToads` call after segmentation centroids are initialized.
That generic wrapper's earlier registration-pyramid initialization uses the
no-atlas overload. The dedicated `AlgorithmLesionToads` wrapper also uses the
no-atlas overload for its initial pyramid. P18czn therefore validates the
atlas-aware overload as a reachable method in the generic multi-TOADS path,
not as the LesionTOADS initial pyramid and not as a registration or
segmentation workflow. The harness contains no expected pooling, optimizer,
or transform-handoff results.
