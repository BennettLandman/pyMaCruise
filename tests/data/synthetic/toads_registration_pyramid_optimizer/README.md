# Synthetic pyramid registration images

This committed synthetic fixture exercises the coarse-to-fine rigid atlas
registration wrapper. It contains no clinical or subject data.

| File | Shape (x, y, z, class) | RAS voxel spacing | Contents |
|---|---:|---:|---|
| `memberships.nii.gz` | 17×15×13×3 | 0.8×1.2×1.5 mm | Float32 membership values from NumPy `default_rng(2)`, uniform on [0.05, 0.9). |
| `atlas_shapes.nii.gz` | 19×17×15×3 | 0.9×1.1×1.3 mm | Float32 synthetic class-prior values from the same generator immediately after memberships. |

Both NIfTI files use positive RAS affine axes and preserve class as the final
fourth dimension. Tests verify the RAS axis codes, shape, and every voxel
against the deterministic generator before running scales 4 and 2. The
different odd input and atlas dimensions exercise independent block truncation
and full-resolution center handling.

`java_reference.json` is helper-level evidence generated by
`scripts/generate_java_toads_registration_pyramid_reference.sh`. The Java
harness reads these exact NIfTI values, calls the preserved source
`ImageFunctions.subsample`, `ParametricTransform`, `RotationMatrix`, and
trilinear sampling/derivative methods, and transcribes the selected
`MultipleToadAtlas` registration helper's scale schedule, exact-membership
coefficient normalization, and gradient line search. It does not call the
production VandyCRUISE `MultipleToadDeformableAtlas.registerShapesPyramid()`
entry point. The actual method comparison uses
`tests/java_reference/ToadsPyramidActualRegistrationHarness.java`; its
step-two scan, deformation-atlas gradient, and NaN-trial clamping are checked
in `tests/test_toads_registration_sampling.py`. The helper-level comparison
covers scale 4 and 2, per-stage starting/final transforms, energies, lambda,
accepted/rejected update counts, per-iteration state, and stopping behavior.
The harness uses the selected rigid registration's `precompute=true` path,
including the scale-specific float32 matrix construction before voxel
coordinate mapping; direct centered-coordinate evaluation has different
rounding and is not the call path used by this source workflow.
It validates this rigid-registration slice only; it does not validate atlas
physical alignment, complete TOADS segmentation, or MaCRUISE workflow outputs.
