# TOADS PowerTable substitution probe

`java_reference.json` was generated by calling the actual selected
VandyCRUISE `PowerTable` class with the selected T1 MPRAGE optimized exponents
`[0.8, 1.0, 1.0]`. The lookup step is the source's `0.000001f` converted to
double (`9.999999974752427e-7`), not the nearest decimal double. Cases include
table endpoints, near-zero values, values around half-step rounding
boundaries, and 1,024 values from Java
`Random(1804)`. Every case also derives three class energies, then performs
the source float32 inverse-energy and normalization steps.

Unquantized `numpy.power` has scalar absolute error below `1e-5`, but its
maximum relative error is 0.426 and the source-normalized membership differs
by up to 0.485, including three changed class winners. This happens near zero
because the Java lookup rounds its input to the float32-derived 1e-6 table
grid before exponentiation. The Python helper therefore applies the selected
index rounding and reuses NumPy `power` at the rounded sample. This small
wrapper matches the tested normalized memberships within `1e-6`; NumPy's
direct unquantized power is not a safe substitution. This probe does not
exercise the complete TOADS membership update or support a
segmentation-equivalence claim. Regenerate with
`scripts/generate_java_toads_powertable_reference.sh`.
