# LesionTOADS dura-removal output slice

This synthetic comparison covers only
`LesionToadSegmentation.generateDuraRemovalOutputs()` in the selected
VandyCRUISE LesionTOADS source. It is a separate adapter from the ordinary
`MultipleToadSegmentation.generateDuraRemovalOutputs()` TOADS method.

The four returned channels, in order, are CSF membership, summed cortical and
cerebellar GM membership, WM-fill membership, and the hard WM mask. The Java
source initializes WM-fill to `lesionMembership + blackHoleMem`, then adds
membership from each atlas class except exact CSF, cortical GM, cerebellar GM,
and Background names. This method does not clip or normalize these arrays.
CSF alias assignments occur in atlas order, so the last `SulcalCSF` or
`Sulcal-CSF` class wins. The hard WM mask is set for selected classes in the
WM-fill loop and for selected names exactly `Cerebellum-GM` or
`CerebellarGM)` in the GM loop. That final string includes a source typo; the
correctly spelled `CerebellarGM` contributes soft GM but is excluded from the
special GM hard-mask predicate. The typo label itself is also admitted by the
WM-fill loop because it is not among that loop's exclusions.

The implementation preserves Java float32 accumulation order: lesion before
black-hole, followed by atlas classes in index order; GM sums are also in
atlas index order. The Java source's closing comment is `} //
generateDuraRemovalOutputs`, after the method's return. The Python adapter is
the method's output projection only; it does not claim to port LesionTOADS
segmentation or the `AlgorithmLesionToads` dispatcher.

## Inputs and phantom

The four checked-in `.nii.gz` files are synthetic true-RAS volumes with shape
`(5, 2, 2)`, positive anisotropic voxel sizes `(1.1, 1.2, 1.3)` mm, and a
nonzero origin. `memberships.nii.gz` has a fourth class axis. The companion
images contain atlas class indices, lesion membership, and black-hole
membership. The 12 class names exercise two CSF aliases, all five recognized
GM aliases, the misspelled `CerebellarGM)` label, Background, and two included
ordinary names that differ only by case. All expected arrays are generated by
the pinned Java excerpt harness, with the same deterministic inputs as
`generate_fixture.py`.

The test loads all image files with `load_nifti_ras`, checks their axis codes,
and compares every voxel of all four outputs exactly against the Java harness
reference. Values above 1 are retained as evidence that outputs are not
clipped.
