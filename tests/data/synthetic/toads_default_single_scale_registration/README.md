# Default TOADS atlas-aware single-scale registration fixture

This synthetic, anisotropic RAS fixture isolates one selected wrapper slice:
atlas-aware top-k initialization, rigid `updateShapeRegistration` at level 1,
and the first `registerShapes() -> registerAllShapes()` iteration. It is not
evidence for the full TOADS workflow, segmentation, atlas alignment, or a
multi-iteration registration trajectory.

`images.nii.gz` is a folded two-channel subject phantom on a 9 x 8 x 7 grid.
`transformed_shapes.nii.gz` contains the corresponding eleven subject-grid
atlas maps used only to initialize memberships. `atlas_shapes.nii.gz` is the
eleven-class template prior on an 11 x 10 x 9 grid. All files have RAS affine
voxel sizes 0.9, 1.2, and 1.45 mm. `generate_fixture.py` recreates the inputs.
Class 0 has strong support so the Java `bestIndex(..., first)` path places the
non-registered `MASK` class in candidate slot zero; the registration kernel
must skip that slot while using the remaining candidates.

`java_reference.json` is generated by
`tests/java_reference/generate_toads_default_single_scale_registration_reference.sh`.
The harness SHA-256 is
`32f99e62674d2712829cd6ac1d57d5f4bc196368c8aef625cce73e5bb15889bf`.
It pins the selected wrapper, `MultipleToadPreprocess`, and
`MultipleToadDeformableAtlas` source hashes in the JSON. The harness reproduces
the relevant selected Java method order and one scale-one rigid optimizer
iteration with `approx=3`, `alignIter=1`, subsampling 2, and an initial transform
of `(0.031, -0.027, 0.022, 0.31, -0.27, 0.22)`.

## Measured comparison

- Membership values and candidate indices match the Java harness exactly.
- The tested method order is atlas-aware `initialApproxMemberships`, rigid
  same-mode `updateShapeRegistration`, then single-scale `registerShapes`.
- For the one tested optimizer iteration, maximum differences were 8 ULP for
  gradient coefficients, 2 ULP for Hessian coefficients, 16 ULP for the trial
  and final transform, and 2 ULP for trial/final energy. Relative energy change
  differed by at most 3.20375e-7 absolute; the final rotation differed by at
  most 6.239861e-8 absolute. Accepted state, zero rejected trials, lambda,
  and per-class bounds matched the pinned Java result.
- A second synthetic call with shifted centroids changes 521 candidate slots
  and changes the final transform by 0.290325 in the largest parameter,
  showing that the registration result depends on selected membership state.
- `align_shapes=False` exercises the same membership and rigid-update handoff
  without calling the optimizer; inputs remain unmodified in both branches.

These measured tolerances cover this one synthetic iteration only. A prior
three-iteration experiment exposed large coefficient sensitivity near the
folded map's piecewise-linear knot boundaries after the first update; it was
excluded from this fixture's claims. Further registration iterations need a
separately scoped numerical study before they can be described as matching.
