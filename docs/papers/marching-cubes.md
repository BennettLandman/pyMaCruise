# Surface extraction: selected JIST source behavior

## Current code path

`extract_levelset_surface` uses a compact Python table generated by executing
the selected JIST `IsoSurfaceOnGrid.solveOriginal(ImageDataFloat, 18, 0,
false)` implementation for all 256 cube sign patterns. The table captures
selected 18/6 connectivity and ordered triangles; Python computes shared edge
vertices, source-style interpolation and float32 point storage. The Java
source and harness are not runtime dependencies. The table metadata records
the source and harness SHA-256 values.

See the [case-template source comparison](../reports/jist-connectivity18-case-template-port-2026-10-08.md)
for focused tests, base/plus saved-level-set comparisons, error bounds and
scope. This is selected-source equivalence for the extraction operation, not
proof that its historical JIST implementation matches a published algorithm
or that upstream full workflows match MATLAB/JIST.

## Historical alternative evaluated

Lewiner T, Lopes H, Vieira AW, Tavares G. “Efficient Implementation of
Marching Cubes’ Cases with Topological Guarantees.” *Journal of Graphics
Tools*. 2003;8(2):1–15. DOI
[10.1080/10867651.2003.10487582](https://doi.org/10.1080/10867651.2003.10487582);
[author-hosted paper and source](https://thomas.lewiner.org/pub/marching_cubes_jgt.html).
The paper and scikit-image implementation were evaluated as an alternative,
but are no longer used by production surface extraction. Earlier comparison
reports remain historical records of that substitution and are superseded by
the selected-source 18/6 case-table implementation.

## Coordinate and source boundaries

The selected Java wrapper sets connectivity 18, iso-level zero and
`inclusive=false`; its source also perturbs values within 0.1 of the iso-level.
PyMaCRUISE keeps that perturbation and transforms array-index vertices through
the complete normalized NIfTI affine to RAS+ millimetres. The RAS conversion is
an output contract, not a claim from the Marching Cubes paper.
