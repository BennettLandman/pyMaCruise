# P36a Synthetic Reference Corpus Provenance Index — 2026-10-01

## Purpose and status

This report indexes representative, committed synthetic reference evidence that
can support the later P36 canonical-reference capture and P37 stage-wise
comparison. It records whether each oracle executes selected upstream source,
uses selected Java excerpts/formulas, or delegates to an external Python
implementation. An exact match to an excerpt or bounded harness is described
as such; it is not described as whole-algorithm equivalence.

This is a read-only inventory. No tests were run to create this report, no
reference outputs were regenerated, and the report itself does not validate any
implementation. P36 remains open: there is **no canonical end-to-end MaCRUISE
base or MaCRUISEplus Java/JIST reference** with complete inputs, outputs,
parameters, environment, and source provenance. Consequently, this index does
not close P36 or remove the workflow blocker described in the plan.

Roadmap context: [P36 and workflow gates in `plan.md`](../../plan.md#L216),
[the P37 stage-wise evidence inventory](p37-stagewise-equivalence-inventory-2026-09-30.md),
and [the selected TOADS/SPECTRE/BET plan](../toads-port-plan.md).

## Cross-cutting provenance and release caveats

- The evidence corpus is heterogeneous. It includes actual selected Java class
  execution, actual selected JIST methods with API stubs, selected Java source
  copies, formula/excerpt harnesses, and tests of an external Python backend.
  Each oracle's method and limits are stated in its fixture README or report;
  never treat all rows as a single Java reference pipeline.
- Fixture-level hashes and source hashes are not uniformly collected in one
  manifest. Where the source hash is absent from the cited artifact, the table
  says so; do not infer a source hash from an output checksum or a current
  checkout. Canonical P36 capture should use one provenance schema for source
  repository/revision, source file hashes, test harness hash, fixture input and
  golden hashes, parameters, runtime/compiler/dependency versions, and known
  stubs or fixed upstream state.
- The harness environment is usually a JDK with narrow headless shims, not the
  complete MIPAV/JIST GUI application. A small number of references require
  original JIST classes/jars (notably Dura TGDM). Harness regeneration steps
  are linked above; their environmental dependencies should be checked and
  recorded when canonical references are recaptured.
- [`license_info.md`](../../license_info.md) is an engineering inventory for
  later Tech Transfer review, not legal clearance. The supplied MaCRUISE,
  VandyCRUISE, and atlas-data redistribution rights remain unresolved where
  no license/permission was located. The MIPAV/JIST notices are preserved, but
  their presence does not by itself grant rights to redistribute source,
  derived data, or binary reference outputs.
- User policy keeps synthetic image fixtures as `.nii.gz`. This index concerns
  synthetic evidence only; it does not add or require actual imaging data.

## P36a exit boundary and next P36 work

P36a is an evidence-inventory substep. It maps the representative corpus and
marks provenance gaps, but P36 still requires a canonical reference package
for the selected end-to-end base path and, where applicable, the plus path.
Those references must capture all consumed inputs and outputs, selected
parameters, environment, source/harness/fixture hashes, source-faithfulness
deviations, and redistribution status. TOADS and Dura-removal coverage must
reach the workflow seams before the full-path package can exist. There is no
canonical end-to-end base/plus reference in the current corpus, so P36 remains
open and P34 remains blocked as recorded in [the roadmap](../../plan.md#L216).
