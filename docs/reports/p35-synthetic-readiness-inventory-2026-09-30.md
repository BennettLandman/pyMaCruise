# P35 Synthetic Readiness Inventory — 2026-09-30

## Purpose and status

This is a readiness inventory for P35, not evidence that the gate passed. It records the test/fixture state visible in the working tree on 2026-09-30 and identifies what still needs review before any subject image is used for implementation validation. No pytest run was performed for this inventory.

P35's acceptance criterion in [`plan.md`](../../plan.md#L217) requires an offline/CI run covering every implemented contract and completed stage, all fixtures synthetic and committed, and an explicit list of missing branches. The most recent plan-level suite summary is **810 passed, 2 expected RAS warnings, 216.16 s** on `d84f2039fe45e6c90cd040a559cc09029a379b7a`, but `plan.md` says that newer P18/P39 changes are not included. The present worktree also contains new untracked tests and fixtures, so that historical result cannot establish the current gate.

## Known missing branches and blockers

1. **Base workflow remains blocked.** P34 is marked Blocked because P18's complete TOADS and Dura behavior is unfinished. The status summary in [`plan.md`](../../plan.md#L17) and the blocker section in [`docs/toads-port-plan.md`](../toads-port-plan.md#L508) identify the remaining full TOADS iteration/registration/evolution path. Existing isolated TOADS and Dura tests cannot prove complete base workflow output/restart behavior.
2. **LesionTOADS and plus workflows remain incomplete.** P39 remains Started; its implemented adapters consume fixed inputs and do not yet assemble the complete spatial/atlas/update/topology/stopping pipeline. P40/P41 integration and plus acceptance remain open, as summarized in [`plan.md`](../../plan.md#L17). The staged synthetic cases cannot stand in for the missing full-run orchestration.
3. **Several new P18/P39 compositions are not yet in a current full-suite report.** The latest summary explicitly excludes recent P18/P39 work. New fixture/test directories listed above are untracked in this snapshot. This is a concrete readiness blocker even where focused Java harness evidence exists.
4. **P37's complete numerical equivalence matrix has not been run.** P35 should inventory all completed contracts but does not itself imply P37 equivalence. The known selected-JIST versus Lewiner surface substitution and documented numerical deviations must remain visible; see [`surface-extraction-java-comparison-2026-09-30.md`](surface-extraction-java-comparison-2026-09-30.md).
5. **Atlas-resource exception needs explicit reviewer disposition.** Atlas image tests load bundled fixed resources, including OASIS-named SPECTRE atlas data, rather than synthetic images. Confirm that fixed atlas assets are an allowed exception to “all fixtures synthetic”; do not classify them as synthetic or as held-out subject cases.
6. **Environment completeness must be recorded.** In particular, ensure ANTsPy is installed so `test_n4.py` does not skip the numerical N4 test. Record Python/dependency versions, skip count, warnings, duration, and exact commit for the gate run.

## Reproducible readiness commands

Run from the repository root after all intended changes and synthetic fixtures are committed:

```sh
.venv/bin/pip install -e '.[ants,dev]'
PYTHONPATH=src .venv/bin/pytest -q
git ls-files tests/data/synthetic | wc -l
git status --short
```

The final two commands are inventory aids, not tests. Before marking P35 passed, confirm the pytest command succeeds offline, the N4 contract is executed rather than skipped, all test fixtures (excluding explicitly accepted fixed atlas resources) are committed and synthetic, the suite includes every newly implemented contract, and the above missing-branch list remains accurate. Then append the exact run result/commit and reviewer/date to P35 in `plan.md`. No actual subject image should be introduced to satisfy this gate.
