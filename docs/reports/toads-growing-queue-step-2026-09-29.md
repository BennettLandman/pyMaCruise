# P18bb — topology-gated TOADS growing event

## Scope

Implemented one `MultipleToadSegmentation.propagateGrowing` queue event in
`toads_process_next_growing_item`. It pops one min-heap item; when the skeleton
voxel is empty, applies the established 18/6 homeomorphic label-change check;
on acceptance it updates segmentation, skeleton, ordering, availability, and
the source class volume, then schedules available six-face candidates using
float32 source priorities. A rejected event restores availability for that
voxel and class. A stale event with a nonempty skeleton only consumes the queue
item. The Java reference retains the source's duplicate homeomorphic call.

## Synthetic Java-reference validation

The test-only Java harness uses the selected 18/6 LUT and `BinaryHeap4D` with
three 5×5×5 synthetic states:

- **Accepted:** center transition is topology-regular, adds the membership to
  the correct float32 class volume, writes the popped priority to center
  ordering, and inserts five available face-neighbors.
- **Rejected:** center transition is topology-critical, segmentation/skeleton
  and volume remain unchanged, and availability for the queued class is
  restored.
- **Stale:** the skeleton center is occupied, so topology is not evaluated
  and the image arrays remain unchanged.

For each case the Python test compares the popped heap item, topology result,
complete segmentation, skeleton and availability arrays, center ordering
bits, all class-volume bits, inserted items, and complete remaining Java heap
pop order. The focused test passes: **1 passed**. The harness is generated by
`scripts/generate_java_toads_growing_queue_step_reference.sh`; input formulas
and source limits are documented in
`tests/data/synthetic/toads_growing_queue_step/README.md`.
