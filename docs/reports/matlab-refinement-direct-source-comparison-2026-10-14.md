## Source-semantic finding

Actual MATLAB `tabulate` probes for uint16 and double arrays show that positive-integer input creates rows 1 through max(label), including zero-count gaps. Inputs `[44,44,45]` and tied `[44,45]` return `maxind=44`; `[100,120,120]` returns `maxind=120`. Thus the original assignment `labels(...)=maxind` equals the modal label for the source's WM/cortical candidates. Python's former distinct-value row index was incorrect. Earlier documentation attributing the low-valued labels to a MATLAB source bug is superseded; there is no need to infer a different compiled source to explain that particular discrepancy.

The fix preserves the original modal-label and first-maximum tie behavior without allocating a dense histogram. The CLI/API mode flags remain accepted. Source order is unchanged. Python's clipped neighborhoods and early stop when no changes occur remain explicit differences from the source; these comparisons establish label-array agreement, not identical logging or iteration counts.
