# P41z JIST transfer downstream surface audit — 2026-10-11

## Result

This synthetic experiment held the saved P41z iteration-11 crop, MaSeg, and
atlas maps fixed, replaced only the Dura GM/WM-fill/WM-mask crop maps with the
selected JIST transfer-plus-crop arrays, then ran the Python topology,
ACE/GVF/TGDM, mesh, and thickness stages with the same selected plus settings.
The source-compatible route did not improve anatomy metrics. WM support inside
the inner surface fell from 59.51% with physical-affine transfer to 0%; GM
support between the surfaces was 0% in both routes. The JIST-crop route
produced 250 closed mesh components per surface, compared with 24 components
in the physical route. Its inner/central/outer level sets differed from the
physical route at 841/5,987/18,240 sign voxels, respectively.

The source-compatible route therefore fails the 97% label-support gate, as
does the physical route. It also has 3.354 mm mean level-set thickness,
0.438 mm median surface thickness, and only 0.0067 mm p05 surface thickness.
This comparison supports keeping physical-affine full-reference RAS transfer
as the recommended default. It does not demonstrate that the transfer
difference caused the underlying ribbon failure, and the source-compatible
experiment is not a Java surface-evolution replay or a complete MaCRUISEplus
run.

## Reproduction

The runner uses the committed synthetic P41z case and the selected Java crop
arrays generated by the preceding transfer/crop comparison:

```sh
PYTHONPATH=src PYTHONNOUSERSITE=1 \
  .venv/bin/python scripts/audit_p41z_jist_transfer_downstream.py \
  --output-dir build/p41z-jist-transfer-downstream
```

The [machine-readable metrics](p41z-jist-transfer-downstream-2026-10-11.json)
record hashes for the runner, crop-ready inputs, Java crop arrays, and
physical-route quality reference. Generated NIfTI/mesh products remain in the
ignored `build/` directory.
