# ACE port progress

This document tracks the Python implementation of the selected MaCRUISE V3
Anatomically Consistent Enhancement (ACE) path. The parameter contract is read
from `run_Ace_jist.m`, `MaACE.java`, and
`MaAnatomicallyConsistentEnhance.java`; algorithm details are read from the
VandyCRUISE ACE classes. Their notices and attribution inventory remain under
`licenses/upstream/` and in `license_info.md`.

## Selected source configuration

- WM threshold for the initial level set: 126.9.
- Gaussian alpha: 1.8.
- Structure-tensor/diffusion alpha: 1.6, 25 diffusion iterations.
- Base MaCRUISE (`UseUpdatedCSFinACE=2`): merge positive updated-CSF values
  to 1 after diffusion and before the speed map.
- MaCRUISEplus (`UseUpdatedCSFinACE=3`): transform CSF to speed, apply the
  second alpha-1.8 Gaussian, then merge positive updated-CSF values to speed
  0.1. This follows the MaACE `MergeSpeedFunction(..., 2)` branch.
- ACE narrow band: time step 0.1, one outer iteration, 10 inner updates,
  curvature threshold 5.0, narrow band `|phi| <= 6`, reinitialization range 4.
- Final membership: exclude weighted distance `<= 0.25` and prohibited voxels;
  use gradient magnitude threshold 0.85, then remove 18-connected components
  of size `<= 60`, promote remaining memberships to 254, and clear the image
  border from both outputs.

## Implemented

`src/pymacruise/ace.py` currently provides:

1. ACE input validation and binary WM closing with the source 18-neighbor
   footprint and border behavior.
2. Initial CSF speed and prohibited-region construction using source thresholds.
3. The Deriche recursive Gaussian and the structure-tensor anisotropic
   diffusion update, including source boundary differences and ten power-method
   iterations. The normal processing mode retains the initialized basis vector
   for stability; `ace_anisotropic_diffusion(source_faithful=True)` reproduces
   the source's divide-by-zero NaNs for stage-level Java comparisons.
4. The source-selected after-diffusion base merge and after-Gaussian plus merge,
   followed by the speed-function blur in the corresponding source order.
5. Unit-speed signed fast marching with subvoxel interface initialization,
   source six-neighbor Eikonal updates, and distance caps.
6. Narrow-band ACE curvature evolution with synchronous updates and signed
   distance reinitialization.
7. Speed-weighted fast marching for travel-time and distance-characteristic
   fields, final ACE membership thresholds, 18-connected cleanup, enhanced-GM
   suppression, and border clearing.
8. Array and NIfTI APIs. The NIfTI API validates a common physical grid,
   reorients non-RAS inputs with a warning, and returns RAS NIfTI images.
   The API returns the cleaned skeleton and the wrapper's thinned skeleton.
   To match `MaAnatomicallyConsistentEnhance.solve`, ThinACE runs before the
   adapter clears the final border on the enhanced-GM and unthinned skeleton
   outputs. ThinACE itself remains separately implemented/tested as P27.

### Zero-tensor exception

The committed 24³ Java comparison phantom contains **0 zero tensors among
13,824 voxels** after smoothing the structure-tensor components. That run
therefore does not validate this corner case. A separate deterministic 3³
zero-tensor test covers all **27 voxels**: normal mode retains its initialized
`(0,0,1)` vector, while source-faithful mode produces NaNs for all three vector
components, matching Java IEEE `0/0` behavior. The source-faithful option is
available on the anisotropic-diffusion stage so callers can compare Java
stages directly; it is not enabled by the full-pipeline API, whose subsequent
finite-field stages intentionally use the robust default. The two behaviors
are reported separately and are not absorbed into numerical tolerances.

For each required ACE skeleton mask, Python and Java are voxel-identical:
the cleaned skeleton has 663 foreground voxels and 1,830 surface vertices;
the thinned result has 341 foreground voxels and 1,490 surface vertices.
Both have Dice 1.0, symmetric mesh Hausdorff 0 mm, and symmetric mean
nearest-surface distance 0 mm (RAS+ mm). This exceeds the user-confirmed
minimum Dice 0.97, maximum Hausdorff 1 mm, and maximum mean surface distance
0.01 mm.

The complete offline test suite passes 142 tests, including all P27/P28 Java
reference checks after regeneration. No real imaging scans have been used.

The reproducible `scripts/benchmark_ace_synthetic.py` run applied the default
25 diffusion iterations and thinning to scaled-up concentric phantoms. On the
2026-09-27 development host, elapsed algorithm time / process peak RSS was
1.68 s / 81.0 MiB at 32³, 3.26 s / 96.0 MiB at 40³, and 5.50 s / 108.4 MiB
at 48³. Peak-RSS increase after imports and input arrays was 9.9, 24.5, and
35.2 MiB respectively. Timings and RSS are host-specific; the script measures
each volume in a fresh process and does not write image data.
