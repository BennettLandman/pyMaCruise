## Distribution and repository policy

- Keep human subject inputs out of Git. Use only synthetic subject images in `tests/data/synthetic/` unless the owner explicitly authorizes a shareable data release. The selected legacy SPECTRE atlas bundle contains OAS1-named images; it is included at the owner's explicit direction and must retain provenance/terms review before any public release.
- Bundle every supplied atlas/data file required at runtime within `data/atlases/`; do not require neighboring source checkouts after installation. Commit assets as regular Git files and keep a SHA-256 manifest. Required files not present in supplied sources, including MNI reference/mask, remain explicit outstanding assets and must be obtained before claiming a fully self-contained full-output release.
- MIPAV and JIST have license/notice files in their source trees; VandyCRUISE, toads-cruise, and the MaCRUISE folder had no top-level license file in this inventory. Check individual source-file headers and obtain project-owner guidance before shipping derived code or bundled atlases.
- The finished Python port should depend on documented Python packages and configured external atlas files where needed; it should not require MATLAB, MIPAV, JIST, or a JVM at runtime.
