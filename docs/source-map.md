# MaCRUISE V3 Source-to-Python Map

This map follows the corrected base workflow selected in [source-baseline.md](source-baseline.md): `run_maCRUISE_v3.m` and `pipeline/maCRUISEpipeline.m`, from MaCRUISE SVN revision 9360. It covers active scientific stages and products from that runner. MaSeg is an input; multi-atlas fusion itself is not run by this entry point.

Legend for Python disposition:

- **Reuse** means an existing library or external-tool Python wrapper should perform a general operation; do not reimplement it without a demonstrated gap.
- **Port faithfully** means the algorithm is MaCRUISE/TOADS/CRUISE-specific and must follow the selected VandyCRUISE/source behavior.
- **Recreate contract** means simple MATLAB orchestration, label rules, file movement, or a MIPAV adapter behavior should be expressed in Python without requiring MATLAB/JIST.
- **Optional** means presentation/interoperability output that does not gate the segmentation result.

## Important source boundaries and gaps

1. VandyCRUISE contains the principal algorithm families used by the pipeline: TOADS (`MedicAlgorithmToads08`), topology correction (`MedicAlgorithmTopologyCorrection`), ACE algorithm classes, generalized GVF (`MedicAlgorithmGradVecFlow`), nested TGDM/CRUISE, and thickness algorithms. It also contains atlas assets for TOADS/CRUISE. These Java algorithms are references to port, not permission to require the MIPAV/JIST runtime in the finished package.
2. The MATLAB wrappers invoke custom classes absent from the supplied `mipav-src` and `VandyCRUISE` Java source trees: `CropBasedOnGM`, `ToadsCruiseSpaceToOriginalSpace`, `MinFilter3D`, `CombineMAandTOADS`, `MaACE`, `MaTGDMcrop`, mesh/levelset helpers, and the custom thickness adapters. Search results do not prove they are absent from every deployed plugin JAR. P05 should locate the deployed JAR/source versions and bundled assets; no mandatory operation may be implemented from a class name alone.
3. `run_GetMABoundary.m` returns a thin-boundary path but the active caller ignores it; its second condition appears to check `Boundary_file` again rather than `Boundary_thin_file`. Do not port this unused output unless a later consumer is found.
4. `run_maCRUISE_v3.m` loads the MASI fusion source path but does not call a fusion function. PyMaCRUISE requires MaSeg input; generating MaSeg from atlases is a distinct project scope.
5. Existing MATLAB wrappers reuse outputs whenever a named file exists, without checking input hashes or parameter compatibility. Python orchestration should use manifests/stage signatures rather than reproduce this stale-output risk.

## Evidence and validation status

The active call chain was read from the selected MATLAB runner, `maCRUISEpipeline.m`, surface/output helpers, and JIST command wrappers. JIST class names were searched in the supplied VandyCRUISE and MIPAV Java source trees; core algorithm families were cross-referenced to the VandyCRUISE source inventory. This is a source-traceability review, not implementation, synthetic validation, or output-equivalence evidence. Those gates remain in later roadmap rows.
